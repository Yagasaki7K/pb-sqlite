## 1. Funcionamento do banco de dados

- Inicializar uma instância SQLite no navegador.
- Executar SQLite em Web Worker, sem bloquear a thread principal.
- Executar comandos SQL (`CREATE`, `INSERT`, `UPDATE`, `DELETE`, `SELECT`).
- Retornar resultados das consultas em formato JavaScript utilizável.
- Suportar parâmetros nas consultas SQL.
- Suportar transações (`BEGIN`, `COMMIT`, `ROLLBACK`).
- Permitir criar, fechar e reabrir uma conexão com o banco.
- Tratar erros do SQLite e retorná-los de maneira compreensível.

## 2. Persistência dos dados

- Utilizar OPFS para armazenar o banco de dados.
- Garantir que os dados permaneçam disponíveis após atualizar ou fechar a página.
- Recuperar automaticamente o banco de dados existente ao inicializar novamente.
- Não apagar ou sobrescrever dados existentes em caso de falha na inicialização.
- Tratar erros de leitura, escrita e indisponibilidade do OPFS.
- Garantir a integridade dos dados durante operações de escrita.

## 3. API pública

- Disponibilizar uma API simples para inicializar o banco.
- Disponibilizar métodos para executar comandos SQL.
- Disponibilizar métodos para consultar dados.
- Disponibilizar métodos para executar transações.
- Permitir configurar o nome e a localização lógica do banco.
- Disponibilizar um método para encerrar corretamente a conexão.
- Disponibilizar tipagens TypeScript.
- Documentar os métodos e seus parâmetros.

## 4. Estabilidade

- Garantir que operações assíncronas sejam executadas corretamente.
- Evitar conflitos entre operações simultâneas.
- Tratar encerramento inesperado do Worker.
- Evitar operações pendentes indefinidamente.
- Garantir que falhas não corrompam o banco de dados.
- Garantir que múltiplas inicializações não causem inconsistências.
- Testar persistência, consultas, transações e recuperação de erros.

## 5. Distribuição

- Configurar o pacote para publicação no npm.
- Disponibilizar suporte a JavaScript e TypeScript.
- Garantir compatibilidade com projetos Vite e Next.js.
- Garantir que a biblioteca não dependa de APIs exclusivas do Node.js durante a execução no navegador.
- Criar um exemplo mínimo de instalação e utilização.
- Disponibilizar um README com instalação, inicialização e exemplos básicos.

## 6. Critérios para lançamento 1.0

- Instalar o PBDB em um projeto novo.
- Inicializar o banco sem erros.
- Criar tabelas e inserir registros.
- Consultar, atualizar e excluir registros.
- Executar e reverter transações.
- Atualizar a página e confirmar que os dados continuam disponíveis.
- Fechar e reabrir o banco sem perder informações.
- Confirmar que erros não comprometem os dados existentes.
- Executar os testes automatizados essenciais.
- Publicar uma versão funcional no npm.

## Minha definição de PBDB 1.0

O PBDB deve ser capaz de fazer isto:

```
const db = await createDB("my-database");

await db.exec(`
  CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL
  )
`);

await db.run(
  "INSERT INTO users (name) VALUES (?)",
  ["Anderson"]
);

const users = await db.query("SELECT * FROM users");

console.log(users);

await db.close();
```

O usuário não precisa conhecer Workers, OPFS, WASM ou detalhes internos do SQLite. Ele precisa apenas conseguir utilizar o banco.

Minha recomendação: congele o escopo da 1.0 nesses requisitos. Não implemente funcionalidades antecipadamente só porque outras bibliotecas oferecem. Primeiro entregue um núcleo pequeno, estável, previsível e funcional. Depois, a própria utilização do PBDB vai indicar quais recursos realmente merecem entrar nas próximas versões.
